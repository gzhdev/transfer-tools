# Spec Delta

## Purpose

为 safecopy 复制引擎提供面向 Windows 10+ 桌面用户的图形界面：以可视化方式收集源文件/目录、配置复制选项、展示进度与日志、处理错误，并支持打包为单文件可执行程序分发。

## ADDED Requirements

### Requirement: 单窗口中文界面布局

GUI SHALL 提供单一主窗口，自上而下分为三段：顶部为源列表区（含「添加文件」「添加文件夹」按钮并支持拖拽投放），中部为目标目录选择与复制选项区，底部为总进度条、当前文件标签、日志区与「开始」「取消」按钮。界面所有面向用户的文案 SHALL 使用中文。

#### Scenario: 窗口布局完整呈现

- **WHEN** 用户启动 GUI
- **THEN** 主窗口依次呈现源列表区、目标与选项区、进度与日志区，且「取消」按钮在未复制时不可用、「开始」按钮在源列表为空或目标目录未设置时不可用

#### Scenario: 界面文案为中文

- **WHEN** 用户查看窗口任意可见控件（按钮、标签、对话框、日志提示）
- **THEN** 文案为中文，无未翻译的占位文本

### Requirement: 源文件收集

GUI SHALL 允许用户通过多选文件对话框、文件夹选择对话框或将文件/文件夹拖入源列表区的方式添加源；重复添加同一路径时 MUST 去重。源为目录时，只有启用递归选项才允许开始复制；未启用递归而源列表含目录时，「开始」操作 MUST 被拒绝并提示。

#### Scenario: 添加文件与文件夹

- **WHEN** 用户点击「添加文件」选择一个或多个文件，或点击「添加文件夹」选择一个目录，或将文件/目录拖入列表区
- **THEN** 这些路径出现在源列表中，且可单独移除或一键清空

#### Scenario: 拖拽去重

- **WHEN** 用户把已在源列表中的路径再次拖入
- **THEN** 列表中该路径只出现一次，不产生重复条目

#### Scenario: 目录源需要递归开关

- **WHEN** 源列表包含目录而递归选项未勾选，用户点击「开始」
- **THEN** 系统拒绝开始并以对话框或日志提示需先启用递归选项，不产生任何目标文件

### Requirement: 复制选项配置

GUI SHALL 提供目标目录选择（浏览对话框或直接输入），并提供与 CLI 对应的选项：递归开关、块大小选择（1~8 MiB 区间内的整数档位，默认 4 MiB）、no-clobber（目标已存在时跳过报错）、no-preserve-metadata（不保留权限与时间戳）。这些选项 MUST 在复制期间锁定不可修改。

#### Scenario: 配置完整选项并开始

- **WHEN** 用户选定目标目录、勾选递归、选择块大小 8 MiB、勾选 no-clobber，点击「开始」
- **THEN** 复制以这些参数执行，且复制进行中所有选项控件处于禁用状态

#### Scenario: 块大小约束

- **WHEN** 用户查看块大小选项
- **THEN** 可选档位均在 1~8 MiB 区间内，默认选中 4 MiB

### Requirement: 复制执行与进度展示

GUI SHALL 复用既有复制引擎按源列表逐一复制；复制期间 MUST 实时展示总进度（已完成文件数/字节进度）、当前正在复制的文件路径，并在日志区追加每个文件的阶段与结果（写入、校验、完成、失败原因）。复制结束后 SHALL 汇总展示成功与失败数量；存在失败时 MUST 明确指示。复制执行 MUST NOT 阻塞界面响应。

#### Scenario: 进度实时更新

- **WHEN** 复制进行中
- **THEN** 总进度条与当前文件标签随每个文件的推进更新，窗口保持可响应（可滚动日志、可点取消）

#### Scenario: 完成汇总

- **WHEN** 全部源处理完毕
- **THEN** 日志与状态指示显示成功/失败数量；全部成功时显示成功提示，存在失败时显示失败提示并列出失败条目

### Requirement: 错误呈现

引擎抛出的复制错误（同源、目标位于源目录内部、校验失败、I/O 错误等）SHALL 同时以模态对话框和日志区条目展示；单个文件失败 MUST NOT 中断其余文件的处理（与 CLI 语义一致）。参数性错误（如源不存在、目录源未启用递归）MUST 在开始复制前一次性报出。

#### Scenario: 复制错误双通道呈现

- **WHEN** 某文件复制时引擎抛出错误（如同源防护触发）
- **THEN** 弹出错误对话框展示该文件与原因，日志区同步记录该错误，其余文件继续复制

#### Scenario: 开始前参数错误

- **WHEN** 源列表中存在已失效（不存在）的路径，用户点击「开始」
- **THEN** 系统在开始复制前报错提示，不产生任何目标文件

### Requirement: 取消与半成品清理

GUI SHALL 提供「取消」按钮，仅在复制进行中可用；取消 MUST 尽快生效：当前文件的安全清理（删除未校验的半成品目标文件）依赖引擎既有失败清理路径完成，不再开始新的文件复制。取消完成后界面 SHALL 恢复到可再次开始的状态。

#### Scenario: 取消正在进行的大文件复制

- **WHEN** 复制大文件过程中用户点击「取消」
- **THEN** 当前文件停止写入、其半成品目标文件被删除，剩余文件不再处理，界面显示已取消状态并恢复可编辑

### Requirement: 与 CLI 共存

GUI SHALL 作为独立入口（如 `safecopy-gui` 命令与打包后的可执行程序）提供，不得改变既有 CLI 的行为与退出码；未安装 GUI 依赖的环境中 CLI MUST 照常工作，尝试启动 GUI 时 MUST 给出明确的缺失依赖提示。

#### Scenario: CLI 行为不受影响

- **WHEN** 在未安装 GUI 依赖的环境运行既有 CLI 命令
- **THEN** CLI 行为与退出码与本变更之前完全一致

#### Scenario: 缺失依赖提示

- **WHEN** 在未安装 GUI 依赖的环境执行 GUI 入口
- **THEN** 系统打印明确的安装提示（指出需安装 GUI 额外依赖）并以非零退出码结束，而非抛出未处理的导入堆栈

### Requirement: Windows 打包交付

项目 SHALL 提供将 GUI 打包为 Windows 单文件可执行程序 `safecopy-gui.exe` 的能力：包含无控制台窗口的窗口化配置、程序版本信息与图标；并提供持续集成配置，在 Windows 构建代理上自动构建并以构件（artifact）形式发布该 exe。打包配置 MUST 同时支持在开发者 Windows 本机以脚本一键构建。

#### Scenario: CI 构建产出 artifact

- **WHEN** 在 Windows 构建代理上触发打包工作流
- **THEN** 工作流产出 `safecopy-gui.exe` 并作为构建构件上传，可供下载

#### Scenario: 本机脚本构建

- **WHEN** 开发者在 Windows 本机运行打包脚本
- **THEN** 产出与 CI 等价的 `safecopy-gui.exe` 单文件（窗口化、含版本与图标）

#### Scenario: Linux 宿主替代验收

- **WHEN** 在 Linux 开发宿主上验证打包链路
- **THEN** 可以无头界面测试与 Linux 目录形态（onedir）冒烟构建代替验证，并在交付文档中说明 Windows exe 须由 CI 或 Windows 本机构建
